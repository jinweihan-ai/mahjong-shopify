# 麻将社群舆情日报/周报 v0.5

> **2026-09-10 店主定：团队周一 09:00 例会要逐日过上一周舆情——日报改为周一至周日每天发（周日也是日报）并写归档表；周报改为周一 08:15 由「报告·FB舆情周」routine 从归档表把上周一至周日七份日报汇总成「团队例会版」发出，必须在 09:00 前到群；周报本身不爬取。2026-09-07 的「周日=周报」规则对本报作废。**


美国麻将玩家的主阵地是 Facebook 群组。本报每天扫描目标公开群近 24h 的帖子,回答三个问题:**有人提到我们或竞品吗?有人正在求购吗?社区在聊什么?** 买家意图帖是媒体线(妍莹)的跟进线索。

## 铁律

1. 数字必须来自当日真实爬取;Apify 失败(重试一次后仍失败)则发简短失败说明,严禁编造
2. 只读监控:严禁用任何账号在 FB 发帖/评论/加群;严禁让 routine 直接访问 facebook.com(反爬风险),一切数据只经 Apify API
3. 帖子原文只做分类与摘要,卡片里单帖引用不超过一句(噪音控制)——**唯一例外:求购线索区(2026-09-03 店主定)直引原帖文本,超 140 词截断**,其余区(热点/雷达/竞品)仍限一句
4. 预算护栏:每天 帖子 actor 1 次 run + 评论 actor 1 次 run(各自失败重试共 ≤2 次),帖子 resultsLimit 50/群;评论只爬**将被点名的帖子**(每天 ≤12 帖,每帖 ≤40 条);v0.5 起周报不爬取(零 Apify 成本);实测帖子单价约 $3.3/千帖,7 群基线月成本约 $30-40,评论另计;连续超标在报尾预警并提请店主裁剪
5. **评论区必读(2026-09-09 店主定)**:凡卡片里带 [原帖](链接) 点名的帖子——雷达命中、求购线索、竞品动向点名帖、社区热点/争议帖——**一律先爬它的评论区,再综合正文+评论区给摘要**,不得只看正文;评论没取到要在该条注明「评论区未取到」

## 评论区综合规则(v0.4,2026-09-09 店主定:"只要带了原帖链接,一定要爬评论区,综合正文和评论区总结")

- **执行顺序**:先按正文完成雷达/分类/选帖 → 汇总所有将被点名的帖子链接 → 一次评论 actor run → 再写摘要。摘要是"正文 + 评论区"的综合,不是正文复述
- **求购线索三行式**(在原两行式上加第三行):首行=中文一句话摘要(加粗;综合正文与评论区,说清楚 TA 要什么、评论区把 TA 往哪推)+ [原帖](链接) + 互动数;次行=原帖英文原文直引(斜体,超 140 词截断);**第三行=「评论区」**:≤40 字中文,写评论区推荐最多的品牌/产品(带次数,如「TML 3 次、OMM 2 次」)、有无人推荐我们、发帖人在评论里是否已表态(已下单/倾向某家/仍在纠结)
- **品牌雷达扩到评论区**:点名帖的评论里出现监控词也算命中,单列时标「(评论区命中)」+ 评论一句摘要 + 情绪;正文零提及但评论区有人推荐我们,是最有价值的信号,放雷达区首位
- **竞品动向**:点名帖评论区里的竞品推荐计入当期竞品频次(与正文分开注明"正文 N 帖 / 评论区 M 次"),并写一句评论区口碑走向(谁被夸、谁被吐槽、吐槽点是什么)
- **社区热点/争议帖**:一句话必须包含评论区的主流意见与分歧点,不只写标题;争议帖点出两边各说什么
- **报尾**加一行「评论区:抓取 N 帖 / M 条评论」;某帖评论未取到时该条末尾标「评论区未取到」

## 日报结构(卡片+图共 2 条,北京 10:00,周一至周日每天)

**窗口口径(2026-09-03 店主定:9点边界固定窗,兼顾新鲜度与同源可复核)**:一律以**北京时间**为准;**每天=日报(v0.5 起含周日),窗口=昨日 09:00 至今日 09:00 的固定 24 小时**——边界固定,不随跑报时刻滚动:当天无论几点跑(定时 10:00 或人工重跑),窗口相同、数字可复核,且距发报仅 1 小时延迟;七份日报的窗口无缝拼接成一周(上周日 09:00 至本周日 09:00),周报只汇总不再另爬。日报卡片标题日期=发报日,KPI 标签写「近24h」并在报尾注明数据窗口(如「窗口:9/2 09:00 - 9/3 09:00 北京时间」)。Apify 的 time 字段是 UTC,先 +8h 转北京时间再按窗口过滤。**截断检测**:某群拉到的最旧一帖仍晚于窗口起点 → 该群窗口未覆盖全,卡末注明「<群名>帖量超采样上限,本期数据可能不全」,不许沉默截断。

- **卡片**(紫 header「📡 社群舆情日报 · M/D」):KPI 三列(窗口内新帖数 | 🎯买家意图帖 | 品牌雷达+竞品命中);「📣 品牌雷达」区(命中必单列:监控词/一句摘要/情绪/[原帖](链接);无命中写"本期无");「🎯 求购线索」区逐条三行式(2026-09-03 店主定两行,2026-09-09 加第三行):**首行=中文一句话摘要(加粗,综合正文与评论区)+ [原帖](链接) + 互动数;次行=原帖英文原文直引**(斜体,换行压成空格;超 140 词在词边界截断加"…");**第三行=「评论区」一句(≤40 字,见评论区综合规则)**;≤5 条,超出计总数(周报清单另按周报节);「竞品动向」一两句(正文频次 + 点名帖评论区频次与口碑走向);「社区热点」一句话(窗口内互动最高帖,写评论区主流意见与分歧点;若另有争议焦点帖也点出,两边各说什么);**报尾列当期监控群名**(来自配置表启用行,如「监控中:Mahjong Community、Mah Jongg That's It」)+「评论区:抓取 N 帖 / M 条评论」+水印

## 飞书卡片渲染边界(2026-09-02 店主反馈,全线统一)

- lark_md 只渲染:**加粗**、*斜体*、[链接](url)、换行;**不渲染 # 标题、```代码块、markdown 表格、竖线/空格对齐**——严禁在卡片里用代码块摆"假表格",缩进在移动端必乱
- 表格型数据两条路:①列少(≤4 列)用 column_set 一行一组(表头行加粗);②**真表格用飞书卡片 2.0 schema 的 table 组件**——整卡结构 `{"schema":"2.0","header":{...},"body":{"elements":[...]}}`,表格元素 `{"tag":"table","page_size":10,"row_height":"low","columns":[{"name":"date","display_name":"日期","data_type":"text","width":"auto"},...],"rows":[{"date":"09-01",...},...]}`;发送端点与 msg_type=interactive 不变,2.0 与经典 1.0 可按卡混用(该卡需要表格才用 2.0)(**2.0 卡不支持 `note` 与 1.0 的 `div`+lark_md 元素,markdown 元素也不支持 `text_color` 属性——水印与脚注用 `{"tag":"markdown","text_size":"notation","content":"<font color='grey'>正文</font>"}`,灰色靠 content 里的 `<font color='grey'>` 内联标签,不靠属性；2026-09-07 竞品周报两次被 230099 拒收后确认:先 note 不支持,改 markdown 后 text_color 报 200621 unknown property**);列多时先精简到关键列(≤6 列)再上表
- 降级为纯文本(msg_type=text)时**必须剥掉全部 ** 等 markdown 记号**——text 消息不渲染任何 markdown,带记号发出去就是垃圾符号
