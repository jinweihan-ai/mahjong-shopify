## 上市准备模块(v0.4 板块×工种线重切+活动/事件双规则;终点=多平台上架开售)

**结构是菱形,不是直线**(2026-09-03 店主定):上游三条素材线共享 → 汇合「素材齐」→ 按平台分叉建品 → 各自汇合「<平台>可上架」→ 汇合「开售日」;上市运营线与素材线并行。**gate 就是 milestone**(Stage-Gate 原义):定价核准这类"某人某日拍板"的把关是事件,进里程碑板块;合规核验、试购走查这类要人干两天的把关是活动,进上市运营线——不单设"门禁"线(试过,甘特里违和)。**甘特两级分组 项目→板块**(里程碑 / 供应链 / 素材 / 建品 / 运营;供应链是最上游,2026-09-04 并入后「B3·里程碑·首批入库」的前置就是「B3·整批·头程运输」(店主定:FBA 与独立站海外仓同一批船只是卡派目的地不同,合并为一个入库事件),供应链滑期自动推到开售日;视图三张:全景·甘特 / 供应链·甘特 / 上市·甘特),组内按工种线→计划开始排序,三条素材链在素材板块里各成一块不搅和;三级分组(再套工种线)能开但里程碑与运营下只有一个子组会出空壳表头,不用。**开售日 = 大货预计入库日**(查尔斯顿:288 套 FBA 预计 9/10),整条主链从它倒排;入库日一动,主链顺延。

**两类追踪对象(按板块判:板块=里程碑 是事件,其余是活动;店主 2026-09-03 点出:甘特天生支持 span,对 event 支持一般)**:
- **活动**(span):有开始/结束、执行方、工期;状态 预测=未开始 / 进行中 / 已完成;逾期 = 今天>计划结束且未完成;另查工期合理性
- **事件**(里程碑 / 外部输入):计划开始=计划结束=目标日;状态 预测=日期是估的 / 已完成=达成 / 风险;不算工期,只算达成(今天>目标日且未完成=未达成);**独有汇合检查:所有前置的计划结束 ≤ 目标日,否则该事件亮风险**——span 做不了,这是事件作为记录存在的价值。外部输入(大货入库/海外仓落仓/样品到位)是别人给的日期,备注含「待核实」的每期晨报点名负责人核日期,核实后由负责人删掉「待核实」
- 飞书甘特的原生「里程碑」是视图级竖线(日期轴悬浮点击建),非记录、无负责人、无前置、API 读不到:只画一根「开售」;事件必须是记录才能挂前置、被 bot 读。甘特「时间条颜色跟随字段」选「工种线」(事件全住里程碑板块,分组已区分;按工种线上色,素材板块里三家外包三色、建品板块里三个平台三色,才是增量信息)。这两处都是手工设置

## 飞书卡片渲染边界(2026-09-02 店主反馈,全线统一)

- lark_md 只渲染:**加粗**、*斜体*、[链接](url)、换行;**不渲染 # 标题、```代码块、markdown 表格、竖线/空格对齐**——严禁在卡片里用代码块摆"假表格",缩进在移动端必乱
- 表格型数据两条路:①列少(≤4 列)用 column_set 一行一组(表头行加粗);②**真表格用飞书卡片 2.0 schema 的 table 组件**——整卡结构 `{"schema":"2.0","header":{...},"body":{"elements":[...]}}`,表格元素 `{"tag":"table","page_size":10,"row_height":"low","columns":[{"name":"date","display_name":"日期","data_type":"text","width":"auto"},...],"rows":[{"date":"09-01",...},...]}`;发送端点与 msg_type=interactive 不变,2.0 与经典 1.0 可按卡混用(该卡需要表格才用 2.0);列多时先精简到关键列(≤6 列)再上表
- 降级为纯文本(msg_type=text)时**必须剥掉全部 ** 等 markdown 记号**——text 消息不渲染任何 markdown,带记号发出去就是垃圾符号
