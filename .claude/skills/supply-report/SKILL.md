## 排期变更监测（v1.8 新增，每日）

防"悄悄延期"——计划日期被静默推迟是供应链最大的隐性风险（查尔斯顿 51 天就是一天天没人喊出来的）：
1. 读"排期快照"表最近一条快照（JSON：record_id → {任务/计划开始/计划结束/实际开始/实际结束/前置}）
2. 与今日全量对比，日报报出：**计划日期变更**（「S3·礼盒·大货 计划结束 9/2→9/7 (+5天) → 负责人」，推迟必报、提前也报）、**新增任务**、**删除任务**、**前置边变更**；无变更整段不出现；对比基线取**最近一条非今日**的快照
3. 对比后把今日快照写入快照表（字段：日期/快照；当日已有记录则更新该记录而非新增），并删除 14 天前的旧快照记录
4. **自愈**：若"排期快照"表不存在，尝试 POST /apps/<APPTOKEN>/tables 创建（名"排期快照"，字段 日期/快照 均文本）；无权限（1254302 RolePermNotAllow）则本段输出一行"⚠ 变更监测待开通：需将 Daily Report Bot 的文档权限提升为「可管理」"，不算失败

## 工期合理性审计（v1.8 新增，每日）——查"事件式填表"

任务被填成单日事件而非有起止的工序，会让 DAG 分析全盘失真（2026-08-25 实例：S4·麻将牌·大货只填了结束日，实际约需 40 天；上架销售全填成开售单日，实际销售窗口约 2 个月）。三条规则（排除已完成）：
1. **日期残缺**：计划开始/计划结束只有其一 → 「⚠ 日期残缺：任务 | 缺计划开始(或结束) → 负责人」
2. **单日事件**：计划开始==计划结束，且工序 ∈ {设计,打样,大货,头程运输,上架销售} → 「🟠 疑似事件式：任务 | 单日 M/D，该工序应为时间段 → 负责人」
3. **工期低于工序下限**（按对象区分，下限故意保守以免误报）：设计 ≥2 天；打样 ≥3 天；大货：麻将牌 ≥30 天、其他对象 ≥7 天；头程运输 ≥15 天；上架销售 ≥30 天 → 「🟠 工期存疑：任务 | 计划 X 天 < 下限 Y 天 → 负责人」
下限值随工期数据积累修订（未来由工期模板库替代）。无问题整段不出现；同一任务同时命中多条只报最严重一条（残缺 > 单日 > 低于下限）

## 将逾期预测（v1.8 新增，每日）

从验尸改预警，两条规则（均排除已完成）：
- **燃烧率**：已开工（实际开始有值）任务，已用天数 ÷ 计划工期（计划结束−计划开始）≥ 80% 且未完成 → 「⏳ 逾期风险：任务 | 已用 X/计划 Y 天 → 负责人」
- **未按计划开工**：计划开始已过 ≥2 天但实际开始为空 → 「🟠 未开工：任务 | 应 M/D 开工，已滞 N 天 → 负责人」
预测行是提前 3-5 天催办的依据，比逾期清单更值钱；无风险整段不出现

## 日报内容（非周一，短报；无事项时"供应链平稳"一行）

1. **逾期任务**：结束日期已过但状态非已完成 → 逐条点名（任务|批次|逾期天数|负责人）
2. **工期合理性审计**（规则见上）
3. **将逾期预测**（规则见上）
4. **排期变更**（规则见上）
5. **3 天内到期任务**：提醒清单（附负责人）
6. **开售倒计时**：查尔斯顿 9/9 / 珠光莫奈 10/8 / 秋冬 11/24（日期随表格更新）
7. 表格新鲜度：全表最后编辑距今 >7 天 → 🟡"排期表 7 天未更新，数据可能失真"

**点名规则**：所有逾期/风险/到期/变更条目末尾带负责人（读"负责人"列；空则不带）——让每一行都有收件人

## 周报内容（周一，全景）

1. 各进行中批次关键路径与最新开售日预测（延误传播重算：任一任务实际滑动 → 沿 DAG 推下游）
2. **并行审计**：无依赖却串行执行的任务对，量化浪费天数
3. **倒排预警**：从目标开售日反推各任务最晚启动日，1 周内到点的列出；第五批 BFCM 缓冲天数每周必报
4. 新批次/新任务变更摘要（基于"排期快照"表做 7 天跨度对比）
5. 建议 ≤2 条带置信度

## 告警（触发才写）

- 🔴 任一任务逾期 >3 天且状态未更新
- 🔴 开售日预测因延误传播而滑动（写明"因 X 任务滑 N 天 → 开售顺延至 Y"）
- 🔴 第五批 BFCM 缓冲 ≤0 天（错过黑五）
- 🟡 排期表 >7 天无编辑

## 飞书卡片渲染边界(2026-09-02 店主反馈,全线统一)

- lark_md 只渲染:**加粗**、*斜体*、[链接](url)、换行;**不渲染 # 标题、```代码块、markdown 表格、竖线/空格对齐**——严禁在卡片里用代码块摆"假表格",缩进在移动端必乱
- 表格型数据两条路:①列少(≤4 列)用 column_set 一行一组(表头行加粗);②**真表格用飞书卡片 2.0 schema 的 table 组件**——整卡结构 `{"schema":"2.0","header":{...},"body":{"elements":[...]}}`,表格元素 `{"tag":"table","page_size":10,"row_height":"low","columns":[{"name":"date","display_name":"日期","data_type":"text","width":"auto"},...],"rows":[{"date":"09-01",...},...]}`;发送端点与 msg_type=interactive 不变,2.0 与经典 1.0 可按卡混用(该卡需要表格才用 2.0);列多时先精简到关键列(≤6 列)再上表
- 降级为纯文本(msg_type=text)时**必须剥掉全部 ** 等 markdown 记号**——text 消息不渲染任何 markdown,带记号发出去就是垃圾符号
