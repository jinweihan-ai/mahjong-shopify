# Averill 供应链专报框架 v1.7

第八份定时报告。数据源：飞书多维表《麻将批次任务拆解》（bitable API，应用凭据在任务配置）。核心方法：把甘特表当 DAG 算——关键路径、并行审计、延误传播、倒排预警。

## 数据与依赖图

- 表：app_token 在任务配置，table tblNPFT2P36NzX9l；**两轴模型（2026-08-24 迁移）**：任务名="批次前缀·对象·工序"（如 B3·礼盒·大货、B4·整批·头程运输；前缀 B1-B5 防关联选择器同名混淆）；字段：批次（=项目）/ 对象（BOM 轴：麻将牌/礼盒/麻将包/桌垫/整批）/ 工序（生命周期轴：设计→打样→大货→到厂运输→工厂打包→头程运输→上架销售）/ **计划开始·计划结束·实际开始·实际结束**（四列分离）/ 状态 / 备注 / 前置任务（依赖图第一数据源）/ 负责人（2026-08-25 新增，默认许世然，后续新品可能是其他人）。"模块"列已废弃勿用。批次×对象×工序 = 天然唯一键
- **计划 vs 实际分析**：延误 = 实际结束 − 计划结束；任务只有计划无实际且计划结束已过 → 逾期；日报/周报延误传播一律基于四列口径。注：历史已完成行的计划列按惯例回填为实际值（原计划未记录），此类行延误恒为 0，不参与延误统计
- **依赖推导规则**（前置任务列为空时兜底，两轴表述）：同对象内 打样←设计、大货←打样、到厂运输←大货；整批·工厂打包←麻将牌·大货+各物料·到厂运输；整批·头程运输←整批·工厂打包（无打包节点则←各对象·大货）；整批·上架销售←整批·头程运输。新任务漏填前置或漏选对象/工序 → 周报点名补填
- **以"前置任务"列为准**，推导规则仅在新任务未填依赖时兜底，并在周报提示补填

## 基线（2026-08-24 农舍批次复盘结论，长期引用）

- 农舍（Charleston）实际 9/9 开售 vs 理论最优 7/20——**串行浪费 51 天**：设计定稿（5/5）后礼盒设计晚启动 29 天、麻将包设计晚启动 40 天；三条物料链工期几乎等长（50-54 天），本可完全藏进麻将链影子里零增时
- 组织教训：**设计定稿 = 所有物料线的发令枪**，礼盒/麻将包设计必须当天启动
- 第五批 BFCM 风险：预测 11/24 开售 vs 黑五 11/27，仅 3 天缓冲

## 写权限边界（v1.7 修订，2026-08-25 店主二次定界：事实与派生分治）

- **人类录入的事实字段完全只读**：计划/实际四日期、状态、批次/对象/工序、前置任务、负责人、备注——发现问题只在报告中点名提醒人类修改；需要机器代改由店主在 Claude 会话下指令
- **机器人自有的派生物由机器人维护**（表内已用 🤖 命名标记"人勿动"）：
  1. 排期表的「进度评级🤖」列（派生列：从四日期+状态确定性重算，人工修改会被每日覆盖）
  2. 「排期快照🤖bot专用·人勿动」表：写入/更新当日快照、清理 14 天前旧快照
- 字段/表按**名称前缀匹配**（"进度评级"/"排期快照"开头），防后续改名断链

## 进度评级列维护（每次运行都做）

刷新「进度评级🤖」单选列：已完成且实际结束>计划结束+1天=🔴 延误；已完成=🟢 按期完成；进行中且计划结束已过=🔴 延误；进行中=🟡 进行中；未启动/预测且计划结束已过=🔴 延误；其余=⚪ 未启动。POST /records/batch_update 仅含该字段、仅更新有变化的记录。该列供甘特视图按颜色渲染（红条=延误）

## 排期变更监测（v1.7 新增，每日）

防"悄悄延期"——计划日期被静默推迟是供应链最大的隐性风险（农舍 51 天就是一天天没人喊出来的）：
1. 读"排期快照"表最近一条快照（JSON：record_id → {任务/计划开始/计划结束/实际开始/实际结束/前置}）
2. 与今日全量对比，日报报出：**计划日期变更**（「B3·礼盒·大货 计划结束 9/2→9/7 (+5天) → 负责人」，推迟必报、提前也报）、**新增任务**、**删除任务**、**前置边变更**；无变更整段不出现；对比基线取**最近一条非今日**的快照
3. 对比后把今日快照写入快照表（字段：日期/快照；当日已有记录则更新该记录而非新增），并删除 14 天前的旧快照记录
4. **自愈**：若"排期快照"表不存在，尝试 POST /apps/<APPTOKEN>/tables 创建（名"排期快照"，字段 日期/快照 均文本）；无权限（1254302 RolePermNotAllow）则本段输出一行"⚠ 变更监测待开通：需将 Daily Report Bot 的文档权限提升为「可管理」"，不算失败

## 工期合理性审计（v1.7 新增，每日）——查"事件式填表"

任务被填成单日事件而非有起止的工序，会让 DAG 分析全盘失真（2026-08-25 实例：B4·麻将牌·大货只填了结束日，实际约需 40 天；上架销售全填成开售单日，实际销售窗口约 2 个月）。三条规则（排除已完成）：
1. **日期残缺**：计划开始/计划结束只有其一 → 「⚠ 日期残缺：任务 | 缺计划开始(或结束) → 负责人」
2. **单日事件**：计划开始==计划结束，且工序 ∈ {设计,打样,大货,头程运输,上架销售} → 「🟠 疑似事件式：任务 | 单日 M/D，该工序应为时间段 → 负责人」
3. **工期低于工序下限**（按对象区分，下限故意保守以免误报）：设计 ≥2 天；打样 ≥3 天；大货：麻将牌 ≥30 天、其他对象 ≥7 天；头程运输 ≥15 天；上架销售 ≥30 天 → 「🟠 工期存疑：任务 | 计划 X 天 < 下限 Y 天 → 负责人」
下限值随工期数据积累修订（未来由工期模板库替代）。无问题整段不出现；同一任务同时命中多条只报最严重一条（残缺 > 单日 > 低于下限）

## 将逾期预测（v1.7 新增，每日）

从验尸改预警，两条规则（均排除已完成）：
- **燃烧率**：已开工（实际开始有值）任务，已用天数 ÷ 计划工期（计划结束−计划开始）≥ 80% 且未完成 → 「⏳ 逾期风险：任务 | 已用 X/计划 Y 天 → 负责人」
- **未按计划开工**：计划开始已过 ≥2 天但实际开始为空 → 「🟠 未开工：任务 | 应 M/D 开工，已滞 N 天 → 负责人」
预测行是提前 3-5 天催办的依据，比逾期清单更值钱；无风险整段不出现

## 日报内容（非周一，短报；无事项时"供应链平稳"一行）

1. **逾期任务**：结束日期已过但状态非已完成 → 逐条点名（任务|批次|逾期天数|负责人）
2. **工期合理性审计**（规则见上）
3. **将逾期预测**（规则见上）
4. **排期变更**（规则见上）
5. **3 天内到期任务**：提醒清单（附负责人）
6. **开售倒计时**：农舍 9/9 / 珠光莫奈 10/8 / 秋冬 11/24（日期随表格更新）
7. 表格新鲜度：全表最后编辑距今 >7 天 → 🟡"排期表 7 天未更新，数据可能失真"

**点名规则**：所有逾期/风险/到期/变更条目末尾带负责人（读"负责人"列；空则不带）——让每一行都有收件人

## 周报内容（周一，全景）

1. 各进行中批次关键路径与最新开售日预测（延误传播重算：任一任务实际滑动 → 沿 DAG 推下游）
2. **并行审计**：无依赖却串行执行的任务对，量化浪费天数
3. **倒排预警**：从目标开售日反推各任务最晚启动日，1 周内到点的列出；第五批 BFCM 缓冲天数每周必报
4. 新批次/新任务变更摘要（基于"排期快照"表做 7 天跨度对比）
5. 建议 ≤2 条带置信度

## 告警（触发才写）

- 🔴 任一任务逾期 >3 天且状态未更新
- 🔴 开售日预测因延误传播而滑动（写明"因 X 任务滑 N 天 → 开售顺延至 Y"）
- 🔴 第五批 BFCM 缓冲 ≤0 天（错过黑五）
- 🟡 排期表 >7 天无编辑
