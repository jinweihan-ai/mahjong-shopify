# 数字溯源(data lineage)设计:点任何一个数,看它从原始记录到公式的整条链

店主 2026-09-16:团队审计 SKU 报告时要能点表格里每一个数字溯源——从原始数据(人填表、API)到显示出来的数字,含计算公式,呈现整个 lineage;依赖不能有环;要方便 debug。

## 现在有什么、缺什么

| 已有 | 缺 |
|---|---|
| 108 节点依赖图(事实源 / 人填表 / 派生),83 条口径编号,校验「每条口径有实现、每个节点有口径」 | **没有环路的显式断言**(现在靠拓扑排序隐含) |
| GUI 点数字 → 口径原文、节点、直接上游、最终来自哪些事实源/人填表、整条链(拓扑序)、核心版本、按天变化 | 链上只有**节点名**,没有这次计算**实际取的值** |

## 目标形态

点「出国每套基础成本 ¥327.26」→ 右栏展开一棵树:

```
出国每套基础成本 327.26  = 层1每套 277.48 + 层2每套 49.78          [C7 · cost.base_cost · 核心 bdc858b · run #31]
├─ 层1每套 277.48 = 采购款 138,739 ÷ 套数 500
│  ├─ 采购款 138,739 = 货款 112,000 + 包材礼盒 26,739                [C1]
│  │  ├─ 货款 112,000 ← 上线前任务 3 行(S2·麻将牌·大货 112,000 …)   [人填 · 点开行]
│  │  └─ 包材礼盒 26,739 ← 上线前任务 4 行 + SKU其他费用 1 行        [人填 · 点开行]
│  └─ 套数 500 ← 项目表 SKU-2｜莫奈升级版 · 套数                      [人填 · 点开行]
└─ 层2每套 49.78 = 跨境发货 22,746 ÷ 出国套数 457
   ├─ 跨境发货 22,746 = 头程 20,831 + 入库费 528 + 丢件采购款 1,387
   │  ├─ 头程 20,831 ← 上线前任务 2 行 + 头程与调拨登记 运费 3 行
   │  ├─ 入库费 528 = YunWMS 入库费 $126.5 × 本 SKU 实收份额 62%     [H2 · API · 镜像 wms_cost 7 行]
   │  └─ 丢件采购款 1,387 = 丢件 5 × 采购每套 277.48                 [C11]
   │     └─ 丢件 5 = 登记 162 − 实收 157(头程与调拨登记 1 行)        [D4 · 点开行]
   └─ 出国套数 457 = 套数 500 − 留国内 38 − 丢件 5
      └─ 留国内 38 ← 头程与调拨登记 工厂→国内办公室 行                [D3 · 点开行]
```

每个节点:值、公式(带实际操作数)、口径编号、实现函数、来源类型(人填表行 / API 或镜像查询 / 派生表某格),叶子能点开:人填表 → 飞书行链接;镜像/API → 显示这次用到的原始行(订单号、日期、金额)与查询窗口;派生 → 跳到那张 derived 表的那一格继续往下点。

## 架构:计算时记录溯源,不是事后猜

1. **核心加 `finance_core.trace`**:`Traced(value, formula, inputs, rule, fn)`,`inputs` 是 `[(名, Traced 或叶子)]`,叶子 = `Leaf(value, ref)`,`ref` 三种:`row`(base/table/record_id/字段)、`query`(镜像表 + 条件 + 命中行数,附前 N 行摘要)、`cell`(derived 表/键/列/as_of)。四则运算保留公式串与操作数。核心函数逐个改成「算值的同时产出 Traced」,先从 cost.base_cost(C7/C8/C9/C11)开始,再 channel 表(I1)、net_revenue(E3)、批次账(I3)、库存(D 系)。
2. **首尔脚本落「溯源🤖」表**:derived 库新表 `lineage`,键 (表, 键, 列, as_of),payload = 溯源树 JSON(叶子只存引用与摘要,不复制整张订单表);每次运行随派生结果一起写,按天可重放、可对比。
3. **GUI**:点数字先查 lineage 有没有这一格;有就渲染可展开的树(默认展两层,值 + 公式 + 口径标签),叶子可点:飞书行直接开、镜像行弹出原始记录、派生格跳转;没有就退回现在的口径面板。
4. **依赖图**:节点扩到 derived 表和脚本(哪个脚本读哪张派生表),加显式无环断言进测试;每格的溯源树本身也是从这张图取子图,树里出现的节点必须都在图上(测试守住)。
5. **Debug 工具**:① 两个日期同一格的溯源树逐节点 diff(「为什么今天和昨天差 ¥5,323」直接指到哪条记录变了);② 输入变了但结果没变 / 结果变了但输入没变 的告警;③ 每条叶子引用都可从 GUI 一键复制查询。

## 分步(每步独立可用)

1. 核心 `trace` 框架 + 无环断言 + 表 1(基础成本 C7–C11)溯源到人填行 → derived `lineage` → GUI 树。约 1 天。
2. 表 2/3/4 渠道账每一行(E1–E3 净收入到镜像订单查询、F 系营销、G 退货、H 物流)。约 1.5 天。
3. 批次账 / 库存现状 / 数量平衡(D 系、I3)。约 1 天。
4. 头寸与跑道、复盘(K 系)。约 1 天。
5. 日期间 diff 与告警。约 0.5 天。

## 边界

- 溯源树只存引用和摘要,不复制原始表;镜像行按需查(GUI 点开时再拉),表里的溯源 JSON 单格 ≤ 50 KB。
- 权限沿用现有角色:finance 看得到 SKU 档案的树,树里叶子若指向店主私有 base(工资、工行流水)则只显示「私有表 · N 行」不给行链接。
