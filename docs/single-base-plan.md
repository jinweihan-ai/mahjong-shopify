# 团队填写收缩到一个多维表格:方案(2026-09-16;店主已定:补货批次 `SKU-n｜名称·R2`、报销单/TikTok 两表/期初盘点团队部分都搬)

店主 9/16 两问:①系统里的 SKU/批次命名能不能沿用「上线前任务」表「项目」列的「SKU-n｜名称」;②能不能把团队要填、要确认的事都收到任务 base(`UubEbqdQBaI8Ybse3wrceBFOnhb`)这一个多维表格里,同一件事不多处填,尽量共享数据。

## 结论

- **命名可以统一,而且应该。** 以「项目」列的 `SKU-n｜名称` 作为**批次**的唯一键;内部代号 S-n 就是 SKU-n(核心 `stock.registry_tag` 已映射,任务名前缀 `S4·` 也一致)。要补一条规则:这张表里「一个项目 = 一个上市批次」,不是产品家族(莫奈 S1/S2 是一个产品两批,店主 9/12 定)。产品家族由「SKU主数据」维护(MONET 家族 = SKU-1 + SKU-2;MONET-4L = SKU-4)。**补货批次要定写法**,建议 `SKU-3｜查尔斯顿·R2`(同产品第二批),不要另起 SKU 号。
- **收缩到一个 base 可以做到:团队填的全进这一个;店主私有的钱不动。** 手段不是把所有列都塞进一张表,而是飞书的**关联字段 + 查找引用**:批次只在「项目」表填一次,其余表用关联指向它,数字互相引用不重复填。

## 目标结构:一个 base「产品与供应链」(现任务 base 改名)

- **「项目」表(新,枢纽)**:一行一个批次。人填:项目键(`SKU-n｜名称`)、产品家族(关联 SKU主数据)、工厂、下单日、计划开售日、**套数**(取代备注解析)、状态(在产/待发/在售/售罄)、单位落地成本·人核、头程丢件·人核、备注。🤖 列(分仓/成本/状态/回本)由 bot 写——等于把私有 base 的批次表搬过来。
- **其余表把「项目/批次号」单选改为关联→项目表**:上线前任务、头程与调拨登记、国内存货去向、SKU其他费用,以及搬进来的 报销单(保留表单)、TikTok结算月表、TikTok达人寄样(或并入去向表「达人寄样·TikTok」)、期初盘点·团队部分、备注登记。
- **共享靠查找引用/汇总**:项目表上直接显示 任务表投入合计、登记发出/在途、去向表出库、其他费用合计、报销归属合计;登记表行上引用项目的工厂/套数;去向表行上引用项目的采购每套(bot 派生列)。
- **写权限**:人填列团队编辑;🤖 列与 🤖 表用字段权限锁定只读;机器人只写 🤖。
- **店主私有 base 只留钱**:工行流水、垫付支出、工资/社保、假设与现金模型四表、回款/头寸/期间费用输出、科目表。SKU主数据(事实映射,不含钱)搬到团队 base。
